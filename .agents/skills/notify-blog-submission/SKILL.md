# Notify Blog Submission

`tech-blog`의 새 글을 현재 주차의 `hanghae-story-forge/notification` 이슈에 제출한다.

## 고정 규칙

- 저장소: `hanghae-story-forge/notification`
- 이슈 목록: `https://github.com/hanghae-story-forge/notification/issues`
- 게시 블로그 기본 URL: `https://www.yeongseo-blog.site/blog/{slug}`
- 날짜와 주차 판정에는 `Asia/Seoul`의 현재 날짜를 사용한다.
- GitHub 댓글 작성은 외부 변경이다. **사용자의 명시적 승인 전에는 절대 작성하지 않는다.**
- 블로그 작업 자체를 먼저 완료한 뒤 댓글 등록을 제안한다. 댓글 승인 대기 때문에 초안 작성이나 요청받은 main 푸시를 막지 않는다.

## 트리거별 처리

다음 중 하나가 발생하면 이 워크플로를 실행한다.

1. 새 블로그 초안 또는 최종본이 `_workspace/*.md`나 `posts/{slug}.md`에 작성됨
2. 사용자가 블로그 변경을 `main`에 푸시하거나 병합해 달라고 요청함

단순 오탈자 수정, 스킬만 수정, 리팩터링처럼 새 글 제출과 무관한 작업에는 실행하지 않는다.

## 절차

### 1. 제출 정보를 확정한다

- `posts/{slug}.md`의 frontmatter에서 `title`을 읽는다.
- 게시 완료 또는 main 푸시 완료 글은 `https://www.yeongseo-blog.site/blog/{slug}`를 사용한다.
- 초안은 사용자가 제공한 공유 URL, 배포 프리뷰 URL, 또는 원격 브랜치에서 접근 가능한 URL을 우선 사용한다.
- 외부에서 열 수 있는 초안 URL이 없다면 그 사실을 밝히고 링크를 받을지, 게시 후 등록할지 사용자에게 묻는다. 로컬 파일 경로를 GitHub 댓글에 쓰지 않는다.
- 가능하면 댓글 제안 전에 URL이 실제로 열리는지 확인한다. 아직 배포 중이면 이를 사용자에게 알린다.

### 2. 해당 주차 이슈를 찾는다

- 열린 이슈를 조회하고 제목이 `N회차(MM월 DD일 ~ MM월 DD일)`인 이슈만 후보로 삼는다.
- KST 현재 날짜가 제목의 시작일과 종료일 사이에 포함되는 이슈를 선택한다. 경계 날짜도 포함한다.
- 번호를 추측하지 않는다. 현재 날짜가 2026-08-01이라면 `4회차(07월 20일 ~ 08월 02일)`인 #85가 대상이다.
- 일치하는 이슈가 없거나 둘 이상이면 댓글을 쓰지 말고 사용자에게 알린다.

### 3. 중복을 검사한다

- 대상 이슈의 기존 댓글을 읽고 같은 URL 또는 같은 글이 이미 제출됐는지 확인한다.
- 이미 있으면 새 댓글을 달지 말고 기존 댓글 링크를 사용자에게 알려 준다.

### 4. 선례에 맞춰 문안을 만든다

게시 글:

```md
[{title}]({public_url})
```

초안:

```md
[{title}]({draft_url}) 초안입니다!
```

사용자가 문구를 따로 지정하면 그 문구를 우선한다. 불필요한 작업 설명, 커밋 해시, 자동화 메타데이터는 붙이지 않는다.

### 5. 승인을 요청한다

다음을 한 번에 보여 주고 댓글을 달아도 되는지 묻는다.

- 대상 이슈 번호·제목·링크
- 실제로 게시할 댓글 전문
- 링크 상태(게시 글, 초안, 아직 배포 중 등)

`오케이`, `달아줘`, `등록해`처럼 해당 제안에 대한 명시적 동의를 받은 경우에만 다음 단계로 간다. 침묵, 이전 작업의 포괄적 승인, main 푸시 요청 자체를 댓글 작성 승인으로 간주하지 않는다. 대상 이슈나 문안이 바뀌면 다시 승인받는다.

### 6. 댓글을 작성하고 검증한다

- GitHub 앱의 이슈 댓글 도구를 우선 사용하고, 사용할 수 없으면 인증된 `gh issue comment`를 사용한다.
- 승인된 문안을 수정하지 않고 그대로 게시한다.
- 게시 후 반환된 댓글 URL 또는 이슈에서 댓글이 보이는지 확인한다.
- 사용자에게 대상 이슈와 댓글 URL을 보고한다.

## 선례

- 윤영서의 게시 글 제출: 주차 이슈에 블로그 URL을 짧게 등록
- 일반 게시 글 제출: `[글 제목](공개 URL)`
- 초안 제출: `[글 제목](공유 URL) 초안입니다!`

선례의 핵심은 짧은 링크 제출이며, 오래된 마이그레이션 댓글에 붙은 `donguel_metadata` HTML 주석은 새 댓글에 복제하지 않는다.

## 실패 처리

- 인증 실패: 댓글을 작성하지 말고 필요한 로그인 절차만 안내한다.
- 링크 확인 실패: 깨진 링크를 자동 등록하지 말고 사용자에게 상태를 알린다.
- 댓글 작성 실패: 자동 재시도는 한 번만 하고, 계속 실패하면 오류와 승인된 문안을 보존해 보고한다.
