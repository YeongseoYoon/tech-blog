# 스타일 가이드 — 기존 포스트 분석

이 블로그의 기존 19개 포스트에서 추출한 스타일 패턴. writer가 톤과 구조를 맞출 때 참조한다.

## 도입부 패턴

### 패턴 1: 개인 경험 시작
> "얼마 전 항해플러스 과제를 진행하면서, 이미 호출한 API는 다시 호출하지 않도록 시도하라는 요구사항이 있었고..."
> "저희 회사의 프로젝트에서는 다음과 같이 쿼리 키를 관리하고 있었습니다."

개인 경험에서 시작하여 독자의 공감을 유도한 뒤 주제로 자연스럽게 전환.

### 패턴 2: 역사/배경 시작
> "JavaScript 개발자라면 누구나 Date 객체를 다루면서 어려움을 겪었던 적이 있을 것입니다."
> "1995년, Brendan Eich는 단 10일 만에 JavaScript를 만들어..."

기술의 역사적 배경으로 시작하여 현재 문제로 연결.

### 패턴 3: 문제 제기 시작
> "프로젝트 규모가 커질수록 쿼리 키 관리는 점점 복잡해지고, 잘못된 관리 방식은 유지보수 문제를 일으킬 수 있습니다."

문제를 먼저 제기하여 독자가 해결책에 관심을 갖게 유도.

## Summary 스타일

기존 포스트의 summary 패턴:
- `"한 걸음 closure 내 맘"` — 제목 키워드를 활용한 말장난
- `"Date객체는 나가있어"` — 유머러스한 한 줄
- `"만능열쇠 키"` — 주제를 은유적으로 표현

summary는 길이 20자 이내의 짧고 위트 있는 표현이 이상적이다.

## 설명 패턴

### 개념 → 코드 → 해설 삼단구조
1. 개념을 1~2문단으로 설명
2. 코드 예제 제시
3. "위 코드에서 일어나는 일을 단계적으로 살펴보겠습니다" → 번호 리스트로 해설

### 비교 구조
- "이러한 문제를 해결하기 위해 다음 세 가지 방안을 검토했습니다"
- 각 방안을 H2로 나누고 장점/단점 리스트 제시

### 인용/레퍼런스
- MDN, 스펙 등 공식 문서 인용 시 `> 인용문` + 링크 형태
- 영문 인용 후 한국어 해설

## 태그 규칙

기존 태그 목록 (재사용 우선):
- `JavaScript`, `TypeScript`, `TANSTACKQUERY`, `DEV`, `CSS`, `PLAYWRIGHT`
- 새 태그가 필요하면 대문자 영문으로 통일
- 태그는 1~3개가 적당

## 금지 사항
- 번역투 문장 ("~것은 ~하다는 것이다")
- 과도한 존칭 ("독자 여러분께서는")
- 불필요한 영어 혼용 (한국어로 자연스럽게 표현 가능한 것)
- 결론부에 "감사합니다" 류의 마무리
